# RFC: 2D Tile Grid & Horizontal SHELF UI for Open PS2 Loader

## Status: Proposed / Banked for Staged Implementation
**Branch Reference:** `oplattice/main` (`https://github.com/coffeedevsolutions/OPLattice`)  
**Target Subsystems:** `src/gui.c`, `src/themes.c`, `include/themes.h`, `src/renderman.c`

---

## 1. Executive Summary
Open PS2 Loader's default interface presents games in a vertical 1D list (`ItemsList`) or an interactive Coverflow carousel (`Coverflow`). The `OPLattice` fork created by CoffeeDevSolutions introduced a multi-row, multi-column 2D Grid view (`Grid`) and an alternative horizontal shelf layout (`SHELF`).

While these layouts provide an attractive modern UI presentation, merging OPLattice's changes directly into the current codebase would collide with existing RiptOPL enhancements:
1. 3D Coverflow carousel state machine, camera easing, and reflection plane math.
2. Favorite games filter toggles and per-device list filters (`devices=usb,hdd...`).
3. Standard D-pad and shoulder button mappings.

This RFC designs a clean, non-destructive abstraction layer that allows 2D Grid and SHELF layouts to exist as selectable, fully theme-compatible presentation modes without degrading or disrupting Coverflow or standard list navigation.

---

## 2. Technical Architecture

### 2.1 UI View Modes
Introduce an explicit view enumeration:
```c
typedef enum {
    UI_VIEW_LIST = 0,     // Traditional vertical 1D ItemsList
    UI_VIEW_COVERFLOW,    // 3D perspective Coverflow carousel
    UI_VIEW_GRID,         // Multi-column, multi-row 2D tile matrix
    UI_VIEW_SHELF         // Horizontal single-row banner shelf
} ui_view_mode_t;
```

### 2.2 2D Navigation Matrix
In vertical lists, D-pad Up and Down decrement and increment the selected index by 1, while Left and Right switch pages or categories. In a 2D Grid:
- **Up / Down:** Moves by `grid_cols` (`index -= cols`, `index += cols`), clamped to list bounds.
- **Left / Right:** Moves by 1 (`index -= 1`, `index += 1`).
- **L1 / R1:** Page Up / Page Down (moves by `grid_cols * grid_rows`).
- **L2 / R2:** Fast alphabetic jump or category switch.

The input dispatch in `gui.c` will delegate directional events based on the active `ui_view_mode_t`, leaving standard list and Coverflow handling untouched when in their respective modes.

### 2.3 VRAM & Texture Management
Displaying a 2D grid of covers requires 12 to 24 textures to be active or resident simultaneously.
- On the PS2 Graphic Synthesizer (GS), total VRAM is strictly 4 MiB, shared between framebuffers, Z-buffer, and texture cache.
- In 1080i or 720p modes, framebuffers consume over 2.5 MiB, leaving less than 1.5 MiB for textures.
- **Requirements:**
  1. Mandatory integration with the `texCheckBudget` clamp implemented in Tier 1.
  2. Textures in grid mode should utilize 4-bit (16-color) or 8-bit (256-color) palettized textures (`GS_PSM_T4` / `GS_PSM_T8`) generated by `palettize-art.py`.
  3. Dynamic LRU eviction to prevent gsKit texture allocator stall loops.

### 2.4 Theme Configuration Schema
```ini
# Grid Element Example in conf_theme.cfg
main_grid:
    type=Grid
    x=40
    y=80
    width=560
    height=340
    cols=4
    rows=3
    item_width=120
    item_height=90
    spacing_x=16
    spacing_y=16
    overlay=grid_focus_frame
```

## 3. Implementation Plan

1. **Phase 1: Input & Navigation Abstraction:** Refactor `gui.c` menu navigation to support 2D matrix traversal without modifying standard list behaviors.
2. **Phase 2: Grid Element Rendering:** Implement `drawGrid` in `themes.c`, rendering viewport-visible cells with highlight frames and smooth scrolling offsets.
3. **Phase 3: Theme Integration & Previewer Support:** Verify compatibility against `thm_GridHard` and standalone `tools/opl-theme-previewer.html`.
