# VMC creation and cancelled-launch audit ? 2026-10-08

Source baseline: Open-PS2-Loader `rebuild/main` at 9ef8d643a739d88a4f4b5fd055a209d0b27299c4. No console reproduction was performed.

## Cancelled native launch: already fixed

Commit afa0ab42 introduced `sbMcemuSlotWord` and per-image slot caches in BDM, SMB, HDD and MMCE. Each image is searched once, within size/4 words. Subsequent launches reuse the cached offsets after settings replace the markers. Every loop rewrites both slots, including inactive slots; HDD explicitly clears an unassigned slot. No marker restoration is needed with this design. Production-helper and call-site regression tests pass, along with the separate cdvdman patch-zone restoration tests. Do not reintroduce a second marker restoration mechanism.

## Creation and allocation

`sysCheckVMC` starts genvmc for a missing or different-sized card. genvmc formats it through sequential block writes, closes it, and reports status. It does not reserve a contiguous extent or defragment the volume. A fresh file and ample free space do not guarantee contiguous allocation. Recreating a saved card can destroy its contents; recovery requires a backup.

The completion path previously used CHECK_CHAIN, whose BDM contract reduces every count other than one to zero. This patch uses GET_FRAGLIST's count-only query after the existing GET_LBA sentinel guard: one means contiguous, more than one means fragmented, and zero/negative is unknown. This distinguishes empty/failed queries from proven fragmentation without disabling native launch checks. It is a diagnosis correction, not a proven repair of the reported allocation failures.

Primary contract: https://github.com/ps2dev/ps2sdk/blob/master/iop/fs/bdmfs_fatfs/src/fs_driver.c (`get_frag_list`, `fs_ioctl2`). The native BDM game path already uses GET_FRAGLIST; no fragment-buffer allocation is required for a count-only call.

## Different runtime limits

Native BDM mcemu writes a contiguous sector range and retains CHECK_CHAIN and the 32-bit LBA range guard at launch. Native APA/PFS mcemu uses bounded inode/block mapping and can reject cards it cannot map. MMCE has a different file-backed contract; unsupported completion ioctls must remain unknown.

The bundled Neutrino revision 7be8de2 maps BDM files with multiple extents and shares a 64-fragment budget across ISO and VMC files (`ee/loader/src/fhi_config.c`). RiptOPL's native contiguity warning is not proof that Neutrino cannot use the file. Its APA path intentionally omits VMC arguments because the bundled core lacks the PFS backing implementation.
