Fork Feature Gaps

Features and fixes that other PS2 loaders, forks and launchers have and RiptOPL does not have yet. Each entry was checked against RiptOPL's own code rather than taken from another project's changelog, and links to where that project implements it.

ℹ A tracking list, not a roadmap
An entry here means another project has something RiptOPL does not; it does not mean the feature is scheduled. Re-audited on 2026-09-22 against rebuild/main at abf14079. This pass re-audits Project Titan Magenta Edition against upstream 2a69c259 (VERSION 0.3.93-rc17), expanding its confirmed code-level gaps from 2 to 10 while preserving Titan's own target/hardware-validation caveats below. The 2026-09-20 pass added NHDDL v1.2.2; the earlier 2026-09-15 update also records PR #658 shipping three former entries (see Notes). Every entry has a short ID whose letter names its source (see Sources surveyed), so it can be referenced in issues and chat. Entries in the Beyond game loading area are general-purpose tools from PS2 environments built on OPL, listed so the survey is complete.

ℹ Titan validation and overlap notes
Titan distinguishes source/host-contract completion from physical-PS2 validation. In particular, Smart IGR, the modern-controller paths and Store/Download path are kept above because this page audits implemented code capabilities, but Titan's own hardware/target-pending labels are preserved rather than treating them as proven compatibility.

Several other Titan capabilities are real but do not get extra T-series IDs because the same RiptOPL gap is already represented elsewhere on this page: direct cover/background fetching overlaps P2, its native wLaunchELF work overlaps B1, Project NES overlaps R1, its launch transition overlaps P5, and wired Xbox USB overlaps P1. Titan's Neutrino/UL launching, VMC support and ordinary PS2RD cheats also have RiptOPL equivalents and are not gaps by themselves.

NHDDL

pcm720/nhddl — a deliberately small Neutrino front-end whose README explicitly keeps OPL-only features such as PADEMU, IGR and cheats out of scope unless Neutrino itself provides them. Audited against the released v1.2.2 code and documentation. The core features most likely to look unique at first glance are already present in RiptOPL: PixelFX/RetroGEM visual Game ID signalling, per-title SD2PSX/MemCard PRO2 card switching, cover art, persistent title caching, remembered last-played selection, global and per-game Neutrino arguments, VMC handoff and the principal Neutrino storage backends. The two remaining differences below are launcher/network conveniences rather than missing game-source support.

IDFeatureWhat it doesSource
N1Generic forward-boot CLI OptionalLaunching NHDDL with -mode=<type> and -dvd=<path> bypasses its UI and hands the target straight to Neutrino; -noinit can reuse an environment whose modules are already loaded. RiptOPL has positional HDD/BDM autolaunch entry points, but not an equivalent documented generic backend/path command line.Forward Boot Mode
N2Reuse SYS-CONF/IPCONFIG.DAT for UDPFS IP OptionalWhen no explicit udpfs_ip is supplied, NHDDL can obtain the PS2 network address from the wLaunchELF/uLaunchELF-style SYS-CONF/IPCONFIG.DAT. RiptOPL's UDPFS path currently uses its own Network settings and the active Neutrino TOML instead of inheriting that shared file.UDPFS documentation
IPCONFIG.DAT fix
ℹ What did not become a gap
NHDDL's visual Game ID output and SD2PSX/MemCard PRO2 per-title switching both have direct RiptOPL equivalents. RiptOPL also already remembers the last-played title, caches parsed ISO metadata, supports global and per-game Neutrino arguments, and can hand VMCs to Neutrino. NHDDL's backend-forcing ELF filename suffixes are a different configuration interface for selecting a device mode, not a separate game-loading capability, so they are not counted independently.

Notes

  • Project Titan Magenta Edition parity checked on 2026-09-22: audited against upstream main@2a69c259 / VERSION 0.3.93-rc17 and RiptOPL rebuild/main@abf14079. Titan's controller, Smart IGR and Store/Download documentation explicitly retains physical-target validation caveats; those rows describe source capability, not a hardware-compatibility guarantee.
  • NHDDL parity checked on 2026-09-20: RiptOPL already has the visual Game ID signal used by PixelFX/RetroGEM hardware, MMCE GameID switching for SD2PSX/MemCard PRO2 on cross-device launches, remembered last-played selection with optional autostart, persistent ISO metadata caching, and global/per-game Neutrino arguments. Those are therefore not N-series gaps.
  • Already in RiptOPL, so not listed: the fix from wOPL PR #435 (remember the last played game when it is the first list entry), PS2RD cheat images (.img), cover art from ART/art.tar (Interface settings), cheats from CHT/cht.tar, the <name>_show_run theme key, RetroAchievements for physical discs, per-game OSD language, virtual memory card creation, and the older USB driver that upstream PR #1752 proposes pinning.
  • Shipped since the survey (PR #658): Ratchet & Clank 3 over SMB (was U5, from upstream PR #1761), Pro Evolution Soccer 2 defaulting to Accurate Reads (was U7, see Compatibility Modes), and Galician and Serbian UI languages (was U8, see Languages). IDs are not reused.
  • wOPL's config format: wOPL moved to libconfig. RiptOPL reads and writes both formats, so files the two loaders share, such as an app's title.cfg, keep working in both.
  • Device names: RiptOPL accepts usb0: and ata0: style names for its boot path and ties each launch to its device by driver name, but reads files through massN:. wOPL uses the typed names throughout. That is a different approach rather than a missing feature, so it is not counted.
  • CFG/cfg.tar: wOPL's README lists it, but neither wOPL nor RiptOPL reads per-game configs from an archive, so it is not counted either.
