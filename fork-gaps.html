Fork Feature Gaps

Features and fixes that other PS2 loaders, forks and launchers have and RiptOPL does not have yet. Each entry was checked against RiptOPL's own code rather than taken from another project's changelog, and links to where that project implements it.

ℹ A tracking list, not a roadmap
An entry here means another project has something RiptOPL does not; it does not mean the feature is scheduled. Re-audited on 2026-09-22 against rebuild/main at abf14079. This pass adds a source-level audit of LUNA by darkladark at main@23112ec (details below), a new visual loader derived from NHDDL and Neutrino, and retains the completed eight-project Awaiting Comparison audit plus the expanded Project Titan Magenta Edition pass. The legacy-variant sweep adds confirmed gaps from E2OPL, Modular PADEMU, historical uOPL, exaconn's RRVE / wheel work and Stable OPL, while moving OPL Daily Build, Grimdoomer OPL and X2P to Checked, nothing missing. Titan was audited against upstream 2a69c259 (VERSION 0.3.93-rc17), expanding its confirmed code-level gaps from 2 to 10 while preserving Titan's own target/hardware-validation caveats below. The 2026-09-20 pass added NHDDL v1.2.2; the earlier 2026-09-15 update also records PR #658 shipping three former entries (see Notes). Every entry has a short ID whose prefix names its source (see Sources surveyed), so it can be referenced in issues and chat. Entries in the Beyond game loading area are general-purpose tools from PS2 environments built on OPL, listed so the survey is complete.

ℹ Titan validation and overlap notes
Titan distinguishes source/host-contract completion from physical-PS2 validation. In particular, Smart IGR, the modern-controller paths and Store/Download path are kept above because this page audits implemented code capabilities, but Titan's own hardware/target-pending labels are preserved rather than treating them as proven compatibility.

Several other Titan capabilities are real but do not get extra T-series IDs because the same RiptOPL gap is already represented elsewhere on this page: direct cover/background fetching overlaps P2, its native wLaunchELF work overlaps B1, Project NES overlaps R1, its launch transition overlaps P5, and wired Xbox USB overlaps P1. Titan's Neutrino/UL launching, VMC support and ordinary PS2RD cheats also have RiptOPL equivalents and are not gaps by themselves.

NHDDL

ℹ What did not become a gap
NHDDL's visual Game ID output and SD2PSX/MemCard PRO2 per-title switching both have direct RiptOPL equivalents. RiptOPL also already remembers the last-played title, caches parsed ISO metadata, supports global and per-game Neutrino arguments, and can hand VMCs to Neutrino. ℹ LUNA overlap and validation notes
LUNA inherits NHDDL's storage discovery, title cache, Neutrino arguments and launch handoff, so the existing N1/N2 audit is not duplicated here. Classic is still fundamentally a list, Collection overlaps RiptOPL's Coverflow, the basic Grid concept is already O1, and ordinary Favorites/disc-art support already exists in RiptOPL. LUNA's square /ART/PSBBN/<TITLE_ID>.png cache is treated as support for its new views rather than another standalone gap. Its HDD-only library filter and ATA-only mass1: probe shortcut are intentional scope/performance choices, not general capabilities RiptOPL lacks.
ℹ LU8 is source-backed but still marked WIP by LUNA
LUNA's source contains the Neutrino-side pad hook, 0x80000598 shutdown RPC and direct ELF-return path, while the v1.0.0-rc.1 release text and FMCB.md also describe direct return. The current top-level README nevertheless marks in-game return as Work in progress. LU8 is therefore counted because it is a concrete Neutrino capability RiptOPL does not have, but it remains explicitly labeled WIP rather than being represented as a finished or hardware-proven feature.
ℹ Hardware evidence scope
LUNA's current FMCB.md says the complete 2026-09-19 FMCB package passed user-reported testing on the tested fat PS2 / adapter setup, while the fidelity/build notes separately distinguish PCSX2 visual checks from physical-console proof for individual UI paths. The rows above describe code that exists in the published tree; they do not generalize one reported package pass to every console, adapter, storage mode or individual visual behavior.

belek666/Open-PS2-Loader modularPademu — a 2020 experimental branch that split PADEMU into controller-specific modules. DS3/DS4 overlap modern OPL, and its Xbox One USB path overlaps P1; the two controller classes below still have no equivalent module in RiptOPL.

IDFeatureWhat it doesSource
MP1Xbox 360 controllers over USB HistoricalA dedicated wired-Xbox-360 module recognizes Microsoft and several third-party VID/PID pairs, translates reports to DualShock 2 input and drives LEDs/rumble. RiptOPL has no xbox360usb PADEMU module.xbox360usb.c
MP2Generic USB HID gamepads HistoricalA generic HID module parses a USB gamepad's HID report descriptor and maps buttons, hats and axes into the emulated DS2 report instead of requiring a controller-specific driver. This is separate from Titan's keyboard/mouse support and BoliviaOS's USB keyboard support.hidusb.c

These are historical source capabilities, not claims of current RiptOPL-era hardware validation. The branch head is 66b93542 from 2020. Its Xbox One USB module is not counted separately because modern Xbox One / Series USB support is already P1.

uOPL (historical)

slimpuggamer/uOPL uOPL-1 — the historical uOPL line mirrored by NathanNeurotic/uOPL. Most of the features that once distinguished it are now directly present in RiptOPL: Favorites, Coverflow, per-game Neutrino, Mode 7, legacy mass: app paths, the extra theme keys, one-button Disable All in the cheat selector and cancellation of pending artwork work during launch.

RRVE / exaconn OPL wheel work

exaconn/Open-PS2-Loader — the repository previously listed here as the wOPL Ridge Racer V Edition. Its current 2026 source has moved beyond that label and contains Logitech wheel work on master, plus a companion Driving-Force-2-negCon-Edition branch. The entry below describes the code that actually exists now rather than inferring features from the old RRVE name.

IDFeatureWhat it doesSource
RR1USB Driving Force wheel with negCon presentation ExperimentalThe DS34 USB path recognizes Logitech wheel devices, parses wheel/pedal reports and applies a spring/auto-centering command. The companion branch presents that wheel through the PS1 negCon protocol (0x23) instead of only emulating a normal DS2, which is useful to titles designed around negCon-style analog steering. RiptOPL's DS34 USB driver has no Logitech dfreport / negCon path.Logitech definitions

Stable Open PS2 Loader (sOPL)

mystyq/Stable-Open-PS2-Loader — a stability-focused fork. Its artwork TAR caching, large-list work, BDM HDD support, game-size fixes, MMCE work and other older changes either exist in RiptOPL or have since been superseded there. One lower-level ATA behavior remains materially different.

IDFeatureWhat it doesSource
S1ATA DRDY waiting for slow-starting SMR / SSD drives FixsOPL's in-game ATAD path adds an ata_wait_until_ready() loop that waits for BUSY to clear and DRDY to assert at driver start and around ATA commands. It was introduced specifically for newer SMR/SSD drives that can take longer to become ready. RiptOPL has its own post-ATAD settling and HDD-detection safeguards, but its current cdvdman/atad.c does not implement this in-driver DRDY wait strategy.commit 3495d55b
current atad.c
ℹ sOPL TAR claims vs. audited source
The May 2026 sOPL release text advertises ART/art.tar, CFG/cfg.tar and CHT/cht.tar. The published release tag points to an older commit, while current master visibly carries the ART reader/cache path. This survey does not turn an unlocated release-note claim into a separate gap. More importantly, RiptOPL rebuild/main now has a unified TAR engine for all three archive kinds, including art_cache.bin, cfg_cache.bin and cht_cache.bin, so none of those archive features is a current RiptOPL gap regardless.
ℹ Awaiting Comparison cleared
All eight variants that were previously reserved for comparison have now been audited. OPL Daily Build, Grimdoomer OPL and X2P produced no remaining unique RiptOPL gap and are recorded in Checked, nothing missing. The five sources above produced six confirmed entries.

Six new gaps survived code comparison; three projects moved to the no-gap table.
  • Project Titan Magenta Edition parity checked on 2026-09-22: audited against upstream main@2a69c259 / VERSION 0.3.93-rc17 and RiptOPL rebuild/main@abf14079. Titan's controller, Smart IGR and Store/Download documentation explicitly retains physical-target validation caveats; those rows describe source capability, not a hardware-compatibility guarantee.
  • NHDDL parity checked on 2026-09-20: RiptOPL already has the visual Game ID signal used by PixelFX/RetroGEM hardware, MMCE GameID switching for SD2PSX/MemCard PRO2 on cross-device launches, remembered last-played selection with optional autostart, persistent ISO metadata caching, and global/per-game Neutrino arguments. Those are therefore not N-series gaps.
  • Already in RiptOPL, so not listed: the fix from wOPL PR #435 (remember the last played game when it is the first list entry), PS2RD cheat images (.img), cover art from ART/art.tar (Interface settings), per-game configs from CFG/cfg.tar, cheats from CHT/cht.tar, persistent TAR index sidecars for all three archive kinds, the <name>_show_run theme key, RetroAchievements for physical discs, per-game OSD language, virtual memory card creation, and the older USB driver that upstream PR #1752 proposes pinning.
  • Shipped since the survey (PR #658): Ratchet & Clank 3 over SMB (was U5, from upstream PR #1761), Pro Evolution Soccer 2 defaulting to Accurate Reads (was U7, see Compatibility Modes), and Galician and Serbian UI languages (was U8, see Languages). IDs are not reused.
  • wOPL's config format: wOPL moved to libconfig. RiptOPL reads and writes both formats, so files the two loaders share, such as an app's title.cfg, keep working in both.
  • Device names: RiptOPL accepts usb0: and ata0: style names for its boot path and ties each launch to its device by driver name, but reads files through massN:. wOPL uses the typed names throughout. That is a different approach rather than a missing feature, so it is not counted.
  • TAR archive status: the older survey note about CFG/cfg.tar is obsolete. RiptOPL rebuild/main now has one indexed/persistently cached TAR engine for ART/art.tar, CFG/cfg.tar and CHT/cht.tar. Consequently, sOPL's TAR work is not a current gap, and an archive claim is counted only when its implementation can be located in the audited source.
