Fork Feature Gaps

Features and fixes that other PS2 loaders, forks and launchers have and RiptOPL does not have yet. Each entry was checked against RiptOPL's own code rather than taken from another project's changelog, and links to where that project implements it.

A tracking list, not a roadmap
An entry here means another project has something RiptOPL does not; it does not mean the feature is scheduled. Re-audited on 2026-09-27 against rebuild/main at abf14079. This pass adds an exhaustive source-level audit of OPHTML by coffeedevsolutions (Blake Coffee) at main@60810bd (v0.10.0, format v7; details below). While presented on its surface as an HTML/CSS UI compiler for PS2 homebrew and memory cards, forensic analysis uncovers a complete standalone OPL-compatible game launcher (ophtml.elf) and environment (opl-env) with 11 confirmed code-level gaps (after excluding overlapping launcher/Neutrino/ISO/texcache features already native to RiptOPL). The survey also retains the source-level audit of LUNA by darkladark at main@23112ec, the completed eight-project Awaiting Comparison audit, and the expanded Project Titan Magenta Edition pass. The legacy-variant sweep adds confirmed gaps from E2OPL, Modular PADEMU, historical uOPL, exaconn's RRVE / wheel work and Stable OPL, while moving OPL Daily Build, Grimdoomer OPL and X2P to Checked, nothing missing. Titan was audited against upstream 2a69c259 (VERSION 0.3.93-rc17), expanding its confirmed code-level gaps from 2 to 10 while preserving Titan's own target/hardware-validation caveats below. The 2026-09-20 pass added NHDDL v1.2.2; the earlier 2026-09-15 update also records PR #658 shipping three former entries (see Notes). Every entry has a short ID whose prefix names its source (see Sources surveyed), so it can be referenced in issues and chat. Entries in the Beyond game loading area are general-purpose tools from PS2 environments built on OPL, listed so the survey is complete. The 2026-10-04 addition compares ORBIT at d015baf7 with RiptOPL rebuild/main@dc6206f6. The 2026-10-06 update adds PS2-Launcher v5.0.0 and re-checks ORBIT v1.0.2, both against RiptOPL rebuild/main@e74ddcec.

What did not become a gap: The console launcher & runtime overlap
While OPHTML hides a standalone console game launcher (console/ophtml.elf) and sample environments (opl-env, channel6), its core game-loading and management capabilities directly overlap existing RiptOPL infrastructure and are not counted as gaps:
  • Neutrino No-IOP-Reset launch handoff: OPHTML launches Neutrino using -qb, -bsd=, and -dvd= through LoadELFFromFileWithPartitionNoReset. RiptOPL already has full native No-IOP-Reset handoff (src/elfldr_noreset.c), copying the child loader into BIOS-unused memory at 0x84000 and passing target paths and arguments to ExecPS2 so Neutrino can read its config and ISO without resetting OPL's live storage mounts.
  • In-memory ISO9660 volume & SYSTEM.CNF title ID extraction: OPHTML traverses sector 16 PVD records and parses SYSTEM.CNF in memory. RiptOPL already performs sector 16 PVD root-directory traversal in memory to extract BOOT2 game IDs and creation timestamps (src/retrogem.c and src/ps2cnf.c).
  • Dynamic cover art streaming & VRAM texture caching: OPHTML's streaming texture slots overlap RiptOPL's dedicated async texture worker (src/texcache.c), which provides lookahead caching, multi-epoch invalidation, chunked staging, memory clamps, and SIO2 controller-bus read throttling.
  • Virtualized list windowing & selection binding: OPHTML's ps2ui_list windowing and selection clamping are standard OPL core features in RiptOPL's item and GUI management.
  • Multi-device & SD2PSX/MMCE support: USB, internal HDD, MX4SIO, and MMCE channel support are already fully functional in RiptOPL's storage drivers and RetroGEM/SD2PSX integration.
Validation status and emulator testing
OPHTML v0.10.0's ophtml.elf launcher has booted and proven its D-pad navigation and list virtualisation inside the Play! emulator in CI (via automated pad input injection and frame diffing). However, because Play! does not emulate USB, HDD or memory card controllers, physical-console bench cases C1–C8 remain formally [open] pending user sitting reports. Conversely, its underlying ps2ui GS rasterization runtime has undergone extensive physical PS2 hardware validation across multiple test sessions (documented in docs/bench-phase1.md and docs/bench-phase2.md).

PS2-Launcher v5.0 overlap
v5.0's Files tab (browse devices, copy, paste and delete files, launch games and ELFs) overlaps B1, and its Xbox 360 support overlaps MP1; those receive no new P-series IDs. Already in RiptOPL: MMCE storage, the full in-game resolution list (RiptOPL also has 720p, 1080i and 1080p), the IGR Path setting, per-game OSD language, and multitap emulation for extra players (set up in Controller Emulation rather than assigned automatically). LUNA overlap and validation notes
LUNA inherits NHDDL's storage discovery, title cache, Neutrino arguments and launch handoff, so the existing N1/N2 audit is not duplicated here. LU8 is source-backed but still marked WIP by LUNA
LUNA's source contains the Neutrino-side pad hook, 0x80000598 shutdown RPC and direct ELF-return path, while the v1.0.0-rc.1 release text and FMCB.md also describe direct return. LU8 is therefore counted because it is a concrete Neutrino capability RiptOPL does not have, but it remains explicitly labeled WIP rather than being represented as a finished or hardware-proven feature.
