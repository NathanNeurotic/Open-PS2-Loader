Vendored from rickgaiser/neutrino iop/ministack/, pinned to commit
06188cce7cd07d2a158cb4b2646c5719fc16a565. Mini IP/UDP stack for the UDPFS transport chain
(parses the ip= arg -> the PS2's own static IP; no DHCP). See ../udpfs_bd/ORIGIN.txt for the
full UDPFS provenance + local changes (PS2SDK Makefile, clang-format).

Local build fix (ps2dev:latest iopfixup): exports.o is listed FIRST in the Makefile's IOP_OBJS
and _retonly is defined AFTER the export table in src/exports.tab, so iopfixup doesn't reject
_retonly as a value-0 .text symbol. Same fix as udpfs_smap / smap_udpbd (commit 2139bcde). The
export table stays POPULATED -- udpfs_bd imports its udp_* functions -- so it must NOT be emptied.
Keep both on re-vendor.

Local discovery fix: udp_packet_send_ll() sends a gratuitous ARP (arp_announce(), an ARP request
for our own IP) before every broadcast from a bound socket -- in practice the UDPRDMA DISCOVERY.
The server answers DISCOVERY with a unicast INFORM; if its ARP cache maps the PS2's IP to another
MAC (stale entry, or a second device on the same address) the INFORM never arrives and the PS2
rediscovers forever. udptty's unbound (port 0) console broadcasts are not announced. Host test:
../udpfs_shared/tests/test_ministack_announce.c.

Local IP-conflict record: handle_rx_arp() notes another MAC claiming our IP (typically the reply to
that announce) and never caches our own IP. arp_ip_conflict() reports it and is APPENDED to the
export table as slot 7 (slots 4-6 unchanged, so udpfs_bd is unaffected). udpfs_ioman answers a
devctl with it so RiptOPL can tell the user. Host test: ../udpfs_shared/tests/test_ministack_conflict.c.
