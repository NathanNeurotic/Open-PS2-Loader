LOCAL CHANGES (marked "RiptOPL" in the sources; .github/scripts/test_ilink_bd_reset.py compiles the
real code against simulated drives and a simulated clock, and fails on the SDK original):
1. src/sbp2_driver.c initConfigureSBP2Device: the login window outlasts the drive's reconnect hold.
   The driver never logs out (SBP2_LOGOUT_REQUEST is defined but never sent) and an IOP reset ends it
   without warning, so the next driver finds the drive still holding the old EXCLUSIVE login. SBP-2
   has the drive keep it for 2^reconnect seconds after the bus reset -- 1 s for the
   MANAGEMENT_ORB_RECONNECT(0) every login here asks for, longer on bridges that round it up -- and
   refuse every new LOGIN meanwhile. The SDK tried 5 times 200 ms apart (~0.8 s), inside the hold, and
   only the next bus reset retries, which a running game never causes: the device never attached and
   CDVDMAN waited forever. Logins are now retried every 200 ms for up to 5 s of elapsed time.
2. src/scsi.c scsi_warmup: TEST UNIT READY is asked at most 300 times, 100 ms apart (30 s, enough for
   a cold 3.5" drive spinning up in its enclosure). The SDK looped with no limit and no delay.
   A READ CAPACITY block length of 0 is a failure (it was a divisor in the log and in every consumer;
   the in-game CDVDMAN divides 2048 by it), and a READ CAPACITY(16) answer with block length 0 is
   ignored.
3. src/scsi.c scsi_connect: the device is published to BDM only after a successful warm-up. The SDK
   ignored scsi_warmup's result and connected a drive whose inquiry, readiness or capacity had failed.
   A failed attempt frees its slot, so the next bus reset can still bring the drive up.

4. src/sbp2_driver.c fetch-agent initialization: clear LOGIN's completed status before publishing
   the dummy ORB, wait for that ORB's own response before freeing it, and propagate a failed
   completion. The old FIFO let Sync return on LOGIN and free a still-pending dummy request.
   Preserve the existing command wait after ambiguous pointer-publication errors: iLinkman can
   return a timeout after the target accepted the request, so early return could release its ORB.
   The matching POPSTARTER copy carries the same changes.
   test_ilink_sbp2_completion.py compiles these real functions from both drivers against immediate,
   delayed, stale, missing and failed completions, plus accepted-but-unacknowledged command
   publication with failed resets. See docs/ILINK_TIMING_INVESTIGATION_2026-10-21.md.

NOT HARDWARE-VERIFIED when added (2026-10-20/21). Worth offering upstream to ps2sdk once confirmed.

5. October 22 geometry audit: READ CAPACITY's last LBA becomes a 64-bit count
   including that sector. RC16 still handles the RC10 sentinel and refuses a
   count that would overflow. The transfer-sector limit is derived from the
   logical block size, and queue_cmd refuses bytes/CDBs exceeding its buffers.
   test_ilink_scsi_geometry.py and test_ilink_command_orb.py cover both copies.
   POPStarter additionally needed the corrected ORB data direction that this
   newer SDK copy already had. See docs/ILINK_CODE_AUDIT_2026-10-22.md.

The manager is now vendored alongside this module under ../iLinkman and applied
to native OPL and the standard Neutrino kit. Its ORIGIN.txt records the same pin
and the manager recovery corrections. No physical-console acceptance yet.

6. October 22 lifetime/ownership follow-up: use per-device resident LOGIN ORB,
   reply, pointer and status FIFO; match status source/length/ORB address. Keep
   one resident command/dummy ORB and reuse the existing 65024-byte allocation
   for reads as well as writes. Serialize publication/status/reset ownership,
   poll completion with a budget and retain storage after an uncertain timeout.
   A late matching status permits reuse; otherwise a fresh driver start is
   required. Do not infer target quiescence from a missing pointer ACK or reset.
   Warm-up passes the remaining elapsed budget to commands; setup propagates
   warm-up failure and frees failed contexts. Reset a completed DEAD command
   agent before retrying, initialize reset data, and decode sense byte 1.
   See docs/ILINK_CODE_AUDIT_2026-10-22.md for tests and hardware limits.
