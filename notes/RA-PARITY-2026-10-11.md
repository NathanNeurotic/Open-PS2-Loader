## Confirmed receiver correction

`ra_drain_rx` bounded the declared UDP payload by its 256-byte scratch buffer but
did not bound it by the actual descriptor length. A truncated frame could therefore
pass stale bytes from a previous packet to the unlock/reset parser. The reference
has `RA_HDR_LEN + up <= len`; restore it without changing socket/RX ownership.
The production-function harness exercises stale tails, one-byte truncation,
complete/padded packets, empty and oversized lengths, and terminator capacity.

## Card parity is not an enable-flag change

The reference card writes an IMAGE transfer into the game's displayed framebuffer.
Checking a free GIF DMA channel and an idle GIF status does not establish ownership
of the GS transfer registers across paths or an outstanding game IMAGE transfer.
The reference documents physical-console display evidence, flicker, and a reported
freeze followed by interrupt-safe/cache-work refinements. Those observations do not
prove general transfer safety. The default remains the pulse. The explicit
experimental opt-in makes the upstream-style renderer available with an in-UI
risk notice; it does not establish safe ownership or console acceptance.

The [Sony EE User's Manual v6.0](https://github.com/ninjadynamics/PS2Docs/blob/main/EE_Users_Manual.pdf),
GIF_STAT reference (printed p. 164), distinguishes
PATH3 interruption, pause, path masks and GS-to-EE direction from queued/active
paths and FIFO occupancy. The experimental refusal mask now includes those
states. The host rasterizer harness checks each mask bit independently and
resumes submission after clearing the state. This closes specific refusal gaps;
it does not solve ownership of GS transfer registers.

## Event snapshot correction

The production pulse previously consumed the DMA event's sequence and kind
directly after checking its commit word. Copy the event first and validate both
the copied commit and the live sequence/commit before changing notification or
reset state. The experimental card now also validates the copied commit, which
its existing live checks omitted. Deterministic host injection covers a new
event arriving after the copy and a copy containing an uncommitted tail; neither
may consume the sequence or trigger reset. A subsequent complete event remains
processable. These checks establish the event contract, not GS timing safety.

## Build isolation

All telemetry, companion protocols, browser and RA-only strings must stay inside
RETROACHIEVEMENTS builds. Shared POPS file hygiene is not a telemetry dependency.
Do not copy a reference's unguarded RA core into ordinary builds.

## Experimental runtime opt-in

`ra_experimental_cards` defaults to 0, resets to Off on a missing config key,
and accepts only integer 1 as enabled. Both interactive and autolaunch config
readers use the same helper. The Network control is selectable only with
Caduceus telemetry enabled. Only opted-in tracked Caduceus PS2 launches reserve
the aligned packet; allocation-fence refusal routes events and VBLANK handling
to the pulse. No new release flavour or EE-core config layout is introduced.
The setting and its risk/help strings are RA-only.
